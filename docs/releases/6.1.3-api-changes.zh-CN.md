# AtomUI 6.1.3 API 变更示例

本文档补充 `6.1.3` 相比 `6.1.2` 的主要破坏性 API 变更和迁移写法。正式版本条目见仓库根目录
`CHANGELOG.md` 和 `CHANGELOG.zh-CN.md`。

Avalonia `12.1.0` 到 `12.1.1` 的依赖升级本身不要求 AtomUI 应用修改源码；本页记录的是同一 AtomUI
发布范围内 Theme、Localization、Upload、Timeline、Tag 和 Separator 的公共契约变化。

英文版本：[6.1.3 API Change Examples](6.1.3-api-changes.md)。

## 快速对照

| 范围 | 6.1.2 | 6.1.3 |
|---|---|---|
| Theme 算法 | 字符串算法 ID | `ThemeAlgorithm` 枚举 |
| Theme 控件包注册 | 分别注册 Token descriptor 和 Theme provider | 生成式 `ControlPackageRegistration` |
| Localization | `LanguageVariant`、`LanguageProvider`、ThemeManager 语言状态 | `LanguageTag`、XLIFF 2.1 Catalog、`ILanguageManager` |
| Upload 文件过滤 | `Accepts` 字符串集合 | `AllowedFileTypes` / `FilePickerFileType` |
| Upload 点击和拖放 | `Upload.IsOpenFileDialogOnClick`、`UploadDefaultDropArea.FilesDropped` | `UploadDropZone` 和 `InputBatchCompleted` |
| Upload 文件内容 | URI 和固定 size 构造 `UploadFileInfo` | `IUploadFileSource` 提供可打开内容流 |
| Timeline 放置 | `Left` / `Right` | `Start` / `End`，并新增 `Orientation` |
| Tag 外观 | `IsBordered` | `TagVariant` |
| Separator 尺寸 | `SizeType` | `CustomizableSizeType` |

## Theme 编译与注册迁移

### 算法字符串改为枚举

`ThemeConfigBuilder.WithAlgorithms` 和 `ControlThemeConfigBuilder.WithAlgorithms` 不再接受字符串。算法
Attribute、descriptor 和运行时状态也统一使用 `ThemeAlgorithm`。

#### 6.1.2 写法

```csharp
var themeConfig = new ThemeConfigBuilder()
    .WithAlgorithms("Default", "Dark")
    .Build();
```

#### 6.1.3 写法

```csharp
using AtomUI.Theme.Algorithms;
using AtomUI.Theme.Configuration;

var themeConfig = new ThemeConfigBuilder()
    .WithAlgorithms(ThemeAlgorithm.Default, ThemeAlgorithm.Dark)
    .Build();
```

自定义算法声明也需要迁移：

```csharp
// 6.1.2
[ThemeAlgorithmAttribute("Dark", 1, ThemeAppearanceEffect.Dark)]

// 6.1.3
[ThemeAlgorithmAttribute(ThemeAlgorithm.Dark, 1, ThemeAppearanceEffect.Dark)]
```

`ThemeAlgorithmAttribute.Id` 和 `ThemeAlgorithmDescriptor.Id` 已被 `Algorithm` 替代。当前算法集合是封闭的
`Default`、`Dark` 和 `Compact`，不再支持任意字符串算法 ID。

### 控件包统一注册

自定义控件包不能再分别调用 `IThemeManagerBuilder.AddControlToken()` 和
`AddControlThemesProvider()`。Token descriptor、Theme asset descriptor 和 Theme provider 必须组成同一个
`ControlPackageRegistration`，并在 `Application.UseAtomUI(...)` 构建阶段注册。

#### 6.1.2 写法

```csharp
application.UseAtomUI(themeBuilder =>
{
    foreach (var descriptor in MyGeneratedThemeSchema.GetControls())
    {
        themeBuilder.AddControlToken(descriptor);
    }

    themeBuilder.AddControlThemesProvider(new MyControlThemesProvider());
});
```

#### 6.1.3 写法

```csharp
application.UseAtomUI(builder =>
{
    builder.AddControlPackage(new ControlPackageRegistration(
        id: "MyCompany.Controls",
        controls: MyGeneratedThemeSchema.GetControls(),
        themeAssets: MyGeneratedThemeAssetManifest.GetDescriptors(),
        controlThemesProvider: new MyControlThemesProvider()));
});
```

示例中的生成类型名称由自定义控件包决定。实际项目应使用 AtomUI Generator 输出的 descriptor 和 asset
manifest，不应在运行时扫描程序集或 AXAML 文件。

Theme definition resolver 同样应在根 Builder 阶段注册：

```csharp
application.UseAtomUI(builder =>
{
    builder.AddThemeDefinitionResolver(new MyThemeDefinitionResolver());
    builder.UseDesktopControls();
});
```

Theme schema、控件 identity、Token schema 和 Theme asset manifest 会在首个 Theme snapshot 编译前冻结；
应用启动后不支持追加控件包或修改已提交的 `ThemeConfig` 集合。

## Localization 生成式 Catalog 迁移

### 删除的旧语言 API

以下类型和入口已经移除：

```text
LanguageCode
LanguageVariant
LanguageVariantTypeConverter
LanguageProvider
ILanguageProvider
LanguageProviderAttribute
LanguageProviderPool
IThemeManagerBuilder.AddLanguageProviders()
IThemeManagerBuilder.WithDefaultLanguageVariant()
```

语言状态不再由 ThemeManager 拥有。应用使用 `LanguageTag`、`ILanguageManager`、`ILocalizer` 和根
`IAtomUIBuilder.UseLanguages()`。

### 配置支持语言

#### 6.1.2 写法

```csharp
application.UseAtomUI(themeBuilder =>
{
    themeBuilder.WithDefaultLanguageVariant(LanguageVariant.zh_CN);
    themeBuilder.AddLanguageProviders(new MyZhCnLanguageProvider());
    themeBuilder.UseDesktopControls();
});
```

#### 6.1.3 写法

```csharp
using AtomUI.Localization;

application.UseAtomUI(builder =>
{
    builder.UseLanguages(
        defaultLanguage: LanguageTags.ZhCN,
        supportedLanguages:
        [
            LanguageTags.EnUS,
            LanguageTags.ZhCN,
            LanguageTags.ZhTW
        ]);

    builder.UseDesktopControls();
});
```

应用 Catalog、组件 Catalog 和静态语言包由 Generator 根据 XLIFF 2.1 输入生成并注册；`UseLanguages()` 只声明
默认语言和应用支持语言，不接收 Provider 或语言包实例。

### 运行时切换语言

#### 6.1.2 写法

```csharp
themeManager.LanguageVariant = LanguageVariant.zh_TW;
```

#### 6.1.3 写法

```csharp
var languageManager = application.GetLanguageManager()
    ?? throw new InvalidOperationException("AtomUI localization is not initialized.");

languageManager.ChangeLanguage(LanguageTags.ZhTW);
```

普通 C# 和 ViewModel 本地化改用 `ILocalizer`：

```csharp
var localizer = application.GetLocalizer()
    ?? throw new InvalidOperationException("AtomUI localization is not initialized.");

string title = localizer.Get(SettingsLangResourceKind.Title);
```

现有 XAML Markup Extension 形式保持不变：

```xml
<TextBlock Text="{atom:DatePickerLangResource Today}" />
```

### Catalog identity 变化

Catalog enum 成员名和 XLIFF `unit id` 现在共同作为唯一 Key。`LanguageCatalogUnitDescriptor.Id` 和 `Name`
收敛为 `Key`；已发布 Key 不得复用于其他语义。

应用、组件和静态语言包必须一起重新构建。不能把 6.1.2 数字 ID Catalog 的程序集或语言包与 6.1.3 Key
Catalog 混合使用；已有第三方语言包应从新的权威 `en-US.xlf` 重新导出、翻译和打包。

## Upload 输入契约迁移

### `Accepts` 改为 `AllowedFileTypes`

`Accepts` 的字符串 pattern/MIME 集合被 Avalonia Storage API 的 `FilePickerFileType` 替代。

#### 6.1.2 写法

```csharp
upload.Accepts = ["*.png", "*.jpg", "image/png", "image/jpeg"];
```

#### 6.1.3 写法

```csharp
using Avalonia.Platform.Storage;

upload.AllowedFileTypes =
[
    new FilePickerFileType("Images")
    {
        Patterns = ["*.png", "*.jpg", "*.jpeg"],
        MimeTypes = ["image/png", "image/jpeg"]
    }
];
```

同一个 `AllowedFileTypes` 同时用于 picker 过滤和 Upload 输入准入。程序化输入、目录展开和 Drop 输入也会按
这些规则校验。

### 点击选择移动到 `UploadDropZone`

`Upload.IsOpenFileDialogOnClick` 已移除。点击选择由组合式 `UploadDropZone` 所有，并通过 `SourceKind` 决定打开
文件还是目录选择器。

#### 6.1.2 写法

```xml
<atom:Upload
    IsOpenFileDialogOnClick="True"
    Files="{Binding Attachments}" />
```

#### 6.1.3 写法

```xml
<atom:Upload Files="{Binding Attachments}">
    <atom:UploadDropZone
        IsOpenFileDialogOnClick="True"
        SourceKind="Files">
        <TextBlock Text="Click or drop files" />
    </atom:UploadDropZone>
</atom:Upload>
```

目录选择使用 `SourceKind="Directories"`。只需要拖放、不需要点击选择时，设置
`IsOpenFileDialogOnClick="False"`。

### Drop 事件改为输入批次结果

`UploadDefaultDropArea.FilesDropped`、`FilesDroppedEvent` 和 `UploadFilesDroppedEventArgs` 已移除。
`UploadDefaultDropArea` 现在只负责默认视觉，`UploadDropZone` 是唯一 DragDrop 输入入口。

不要在 DropArea 上接收原始 `IStorageFile` 集合。需要记录输入结果、拒绝原因或批次失败时，监听
`Upload.InputBatchCompleted`：

```csharp
private void HandleInputBatchCompleted(
    object? sender,
    UploadInputBatchCompletedEventArgs e)
{
    if (e.Status == UploadInputBatchStatus.Failed)
    {
        LogInputFailure(e.BatchId, e.FailureReason);
        return;
    }

    foreach (var rejected in e.RejectedItems)
    {
        LogRejectedFile(rejected.Name, rejected.Reason, rejected.Message);
    }
}
```

```xml
<atom:Upload
    Files="{Binding Attachments}"
    InputBatchCompleted="HandleInputBatchCompleted">
    <atom:UploadDropZone DirectoryDropMode="RecursiveFiles">
        <atom:UploadDefaultDropArea />
    </atom:UploadDropZone>
</atom:Upload>
```

### `UploadFileInfo` 改为可打开的文件源

`UploadFileInfo` 不再假设每个文件都有可访问的本地 URI、固定 size 或可重复打开的路径。调用方必须提供
`IUploadFileSource`，每次 `OpenReadAsync()` 调用返回新的可读流。

#### 6.1.2 写法

```csharp
var file = new UploadFileInfo(
    name: "report.pdf",
    filePath: new Uri(filePath),
    size: new FileInfo(filePath).Length);
```

#### 6.1.3 写法

```csharp
sealed class LocalUploadFileSource(string filePath) : IUploadFileSource
{
    public ValueTask<Stream> OpenReadAsync(
        CancellationToken cancellationToken = default)
    {
        cancellationToken.ThrowIfCancellationRequested();
        return ValueTask.FromResult<Stream>(File.OpenRead(filePath));
    }
}

var fileInfo = new FileInfo(filePath);
var file = new UploadFileInfo(
    name: fileInfo.Name,
    source: new LocalUploadFileSource(filePath),
    path: new Uri(filePath),
    size: fileInfo.Length,
    contentType: "application/pdf");

await upload.EnqueueFilesAsync([file]);
```

如果 source 持有临时文件、StorageItem lease 或其他资源，其生命周期会转移给 Upload，直到对应上传执行退出、
文件被移除或控件释放。

### 自定义准入策略

需要业务校验时实现 `IUploadAdmissionPolicy`，返回工厂方法创建的决定：

```csharp
sealed class AttachmentAdmissionPolicy : IUploadAdmissionPolicy
{
    public ValueTask<UploadAdmissionDecision> EvaluateAsync(
        UploadAdmissionContext context,
        CancellationToken cancellationToken = default)
    {
        return context.File.Size > 10 * 1024 * 1024
            ? ValueTask.FromResult(UploadAdmissionDecision.Reject(
                "file-too-large",
                "The file exceeds the 10 MB limit."))
            : ValueTask.FromResult(UploadAdmissionDecision.Accept());
    }
}
```

```xml
<atom:Upload
    AdmissionPolicy="{Binding AttachmentAdmissionPolicy}"
    CountOverflowBehavior="RejectExcess"
    MaxCount="5" />
```

## Timeline 逻辑方向迁移

`TimelineMode.Left` 和 `TimelineMode.Right` 被逻辑方向 `Start` 和 `End` 替代，以支持 RTL 和水平布局。

| 6.1.2 | 6.1.3 |
|---|---|
| `TimelineMode.Left` | `TimelineMode.Start` |
| `TimelineMode.Right` | `TimelineMode.End` |
| `IndicatorLeftModeMargin` | `IndicatorStartModeMargin` |
| `IndicatorRightModeMargin` | `IndicatorEndModeMargin` |

#### 6.1.2 写法

```xml
<atom:Timeline Mode="Left" />
```

#### 6.1.3 写法

```xml
<atom:Timeline
    Mode="Start"
    Orientation="Vertical" />
```

水平时间线使用相同的逻辑放置模式：

```xml
<atom:Timeline
    Mode="Alternate"
    Orientation="Horizontal" />
```

`Orientation` 默认仍为 `Vertical`。自定义 Theme/Token 覆盖需要同步使用 Start/End 资源名称。

## Tag Variant 和可选择 Tag 迁移

### `IsBordered` 改为 `TagVariant`

`Tag.IsBordered` 已移除，新的 `Variant` 支持 `Filled`、`Solid` 和 `Outlined`，默认值为 `Filled`。

#### 6.1.2 写法

```xml
<atom:Tag
    Text="Release"
    IsBordered="True" />
```

#### 6.1.3 写法

```xml
<atom:Tag
    Text="Release"
    Variant="Outlined" />
```

原 `IsBordered="False"` 没有完全等价的兼容模式。通常可按视觉意图选择 `Filled`；需要高对比实色背景时使用
`Solid`。Preset、Status 和自定义颜色会与 Variant 共同决定背景、前景和边框。

### 可选择场景改用 CheckableTag

普通 Tag 继续负责展示、颜色和关闭操作。二元选择使用 `CheckableTag`，集合选择使用
`CheckableTagGroup`：

```xml
<atom:CheckableTag
    Content="Preview features"
    IsChecked="{Binding IsPreviewEnabled}" />
```

单选集合：

```xml
<atom:CheckableTagGroup
    Options="{Binding Categories}"
    CheckedItem="{Binding SelectedCategory}" />
```

多选集合：

```xml
<atom:CheckableTagGroup
    Options="{Binding Categories}"
    IsMultiple="True"
    CheckedItems="{Binding SelectedCategories}" />
```

`CheckableTag` 不提供普通 Tag 的 `TagColor`、`Variant`、`IsClosable` 或关闭事件。

## Separator 可定制尺寸迁移

Separator 的 `SizeType` CLR 类型从 `SizeType` 改为 `CustomizableSizeType`，并实现
`ICustomizableSizeTypeAware`。

常规 XAML 中的 `Small`、`Middle` 和 `Large` 名称保持不变：

```xml
<atom:Separator SizeType="Small" />
```

直接读写强类型属性的 C# 代码需要修改：

```csharp
// 6.1.2
separator.SizeType = SizeType.Small;

// 6.1.3
separator.SizeType = CustomizableSizeType.Small;
```

`Custom` 不应用 AtomUI 的预设 block margin，由调用方或 owner style 提供间距：

```xml
<atom:Separator
    SizeType="Custom"
    Margin="0,4" />
```

如果自定义方法、接口或 ViewModel 属性声明为 `SizeType`，也需要同步改成 `CustomizableSizeType`，不能依赖隐式
枚举转换。

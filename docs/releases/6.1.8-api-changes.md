# AtomUI 6.1.8 API Change Examples

AtomUI 6.1.8 changes three public extension boundaries: DataGrid data/query state, image-loading sources and cache policy, and Control Design Token inheritance. This guide shows the required migrations from 6.1.7.

Chinese version: [AtomUI 6.1.8 API 变更示例](6.1.8-api-changes.zh-CN.md).

## Quick reference

| Area | 6.1.7 | 6.1.8 migration |
| --- | --- | --- |
| DataGrid | Collection-backed `ItemsSource`, mutable `DataGridCollectionView` query state and item/index selection | Wrap local data in `DataGridLocalSource<T>` or implement `IDataGridSource`; use immutable `DataGridQuery`, `DataGridSelectionState` and stable row/field keys |
| Image loading | `ImageLoadSource`, `ImageLoadSourceKind` and combined `ImageCacheMode` | Construct the appropriate closed `ImageSource` subtype and choose `ImageCacheReadPolicy` and `ImageCacheStoragePolicy` independently |
| Control Design Token | Concrete token types could remain unsealed and be used as inheritance layers | Make terminal `[ControlDesignToken]` types `sealed`; introduce explicitly marked abstract token layers for shared inheritance |

## DataGrid: use range sources and immutable state

### Wrap local collections in `DataGridLocalSource<T>`

`DataGrid.ItemsSource` no longer accepts an arbitrary `IEnumerable`. It accepts `IDataGridSource`, whose schema defines stable row keys and queryable fields.

Before:

```csharp
public ObservableCollection<Customer> Customers { get; } = LoadCustomers();
```

```xml
<atom:DataGrid ItemsSource="{Binding Customers}" />
```

After:

```csharp
public sealed class CustomersViewModel : IDisposable
{
    private readonly ObservableCollection<Customer> _customers = LoadCustomers();

    public CustomersViewModel()
    {
        Customers = DataGridLocalSource.Create(
            _customers,
            DataGridLocalSourceDescriptor.For<Customer>(
                    static customer => DataGridRowKey.FromInt64(customer.Id))
                .Field(CustomerFields.Name, static customer => customer.Name)
                .Field(CustomerFields.CreatedAt, static customer => customer.CreatedAt));
    }

    public DataGridLocalSource<Customer> Customers { get; }

    public void Dispose() => Customers.Dispose();
}

public static class CustomerFields
{
    public static readonly DataGridFieldId Name = new("name");
    public static readonly DataGridFieldId CreatedAt = new("createdAt");
}
```

```xml
<atom:DataGrid ItemsSource="{Binding Customers}">
    <atom:DataGrid.Columns>
        <atom:DataGridTextColumn Header="Name"
                                 FieldId="{x:Static vm:CustomerFields.Name}"
                                 Binding="{Binding Name}" />
        <atom:DataGridTextColumn Header="Created"
                                 FieldId="{x:Static vm:CustomerFields.CreatedAt}"
                                 Binding="{Binding CreatedAt}" />
    </atom:DataGrid.Columns>
</atom:DataGrid>
```

The owner of a `DataGridLocalSource<T>` must dispose it. The row-key projection must be stable and unique. Register every field used for sorting, filtering or grouping in the descriptor; display-only columns may omit `FieldId`.

For remote or virtual data, implement `IDataGridSource` directly:

```csharp
public interface IDataGridSource
{
    DataGridSourceSchema Schema { get; }

    ValueTask<DataGridRangeResult> FetchAsync(
        DataGridFetchRequest request,
        CancellationToken cancellationToken);

    event EventHandler? Invalidated;
}
```

`FetchAsync` receives the immutable query, page, group-expansion, range and snapshot scope. Return only the requested range and honor cancellation. Implement optional editable, movable, key-lookup or bulk-selection interfaces only when the source supports those capabilities.

### Replace mutable collection-view query APIs

The old `DataGridCollectionView` family and mutable sort/filter/group description collections have been removed. Construct an immutable `DataGridQuery` or use the grid's query helpers.

Before:

```csharp
grid.CollectionView!.SortDescriptions.Add(
    new DataGridSortDescription(nameof(Customer.Name), ListSortDirection.Ascending));
```

After:

```csharp
grid.Query = grid.Query.WithSorts(
    [new DataGridSort(new DataGridFieldId("name"), DataGridSortDirection.Ascending)]);

// Or let DataGrid validate and update the current query:
grid.SetSort(new DataGridFieldId("name"), DataGridSortDirection.Ascending);
```

The following column members were removed: `SortMemberPath`, `CustomSortComparer`, `FilterMemberPath`, `FilterTextMemberPath`, `FilterValueMemberPath`, `FilterChildrenMemberPath` and related member-path filter properties. Use `DataGridColumn.FieldId` and declare supported sort/filter/group behavior in the source schema. `DataGridColumn.CanUserSort` is now nullable; `null` inherits the grid-level policy and source capability.

Group APIs now use stable group keys:

```csharp
grid.CollapseGroup(groupKey);
grid.ExpandGroup(groupKey);
```

Code that passed `DataGridCollectionViewGroup` to `CollapseRowGroup` or `ExpandRowGroup` must use the `DataGridGroupKey` supplied by the range-source result.

### Replace item/index selection with declarative selection

`SelectedIndex`, `SelectedItem`, `SelectedItems`, `CollectionView` and the routed `SelectionChangedEvent` were removed. Selection is represented by immutable `DataGridSelectionState`; the current row is identified by `CurrentRowKey`.

Before:

```csharp
grid.SelectedIndex = 0;
grid.SelectionChanged += OnSelectionChanged;
```

After:

```csharp
var key = DataGridRowKey.FromInt64(customer.Id);

grid.Selection = new DataGridSelectionState(
    explicitKeys: [key],
    allMatchingQuery: null,
    indexIntervals: [],
    excludedKeys: []);
grid.CurrentRowKey = key;

grid.SelectionChanged += (_, args) =>
{
    DataGridSelectionState oldSelection = args.OldSelection;
    DataGridSelectionState newSelection = args.NewSelection;
};
```

`SelectionChanged` is now a normal `EventHandler<DataGridSelectionChangedEventArgs>`. It reports old and new declarative states and does not materialize unloaded items. Use stable row keys rather than view indexes when persisting selection.

## Image loading: construct typed `ImageSource` values

`ImageLoadSource` and `ImageLoadSourceKind` were replaced by the closed `ImageSource` hierarchy and `ImageSourceKind`. Replace factory calls as follows:

| 6.1.7 | 6.1.8 |
| --- | --- |
| `ImageLoadSource.FromUri(uri)` | `new HttpImageSource(uri)` for HTTP(S), or the appropriate concrete source |
| `ImageLoadSource.FromFile(path)` | `new FileImageSource(path)` |
| `ImageLoadSource.FromAsset(uri)` | `new AssetImageSource(uri)` |
| `ImageLoadSource.FromStorageFile(file, cacheKey, version)` | `new StorageFileImageSource(file, revision)` |
| `ImageLoadSource.FromBytes(bytes, cacheKey, version)` | `new BytesImageSource(bytes, displayName)` |
| `ImageLoadSource.FromStream(open, cacheKey, version, name)` | `new StreamImageSource(open, identity, revision, name)` |
| `ImageLoadSource.FromImage(image, cacheKey)` | `new BorrowedImageSource(image, displayName)` |

Before:

```csharp
var item = new ImagePreviewItem(
    ImageLoadSource.FromUri(new Uri("https://example.test/photo.png")))
{
    RequestOptions = new ImageRequestOptions
    {
        CacheMode = ImageCacheMode.Reload
    }
};
```

After:

```csharp
var item = new ImagePreviewItem(
    new HttpImageSource(new Uri("https://example.test/photo.png")))
{
    RequestOptions = new ImageRequestOptions
    {
        CacheRead = ImageCacheReadPolicy.RefreshSource,
        CacheStorage = ImageCacheStoragePolicy.MemoryAndDisk
    }
};
```

`ImageSource.Parse` and `ImageSource.TryParse` remain available for supported absolute HTTP(S), `avares`, `file` and platform path strings. Prefer explicit constructors when source kind and ownership are known.

### Split cache read behavior from cache storage

`ImageCacheMode` combined two independent decisions. Replace it with `ImageRequestOptions.CacheRead` and `CacheStorage`:

| Former mode | `CacheRead` | `CacheStorage` |
| --- | --- | --- |
| `Default` | `ValidateSource` | `MemoryAndDisk` |
| `Reload` | `RefreshSource` | `MemoryAndDisk` |
| `NoStore` | choose the required read policy | `None` |
| `CacheOnly` | `CacheOnly` | choose the required storage policy |

`ValidateSource` is the normal default. `RefreshSource` forces source access for that request, `PreferCache` may use a cache entry without normal source validation, and `CacheOnly` fails rather than accessing the source on a miss.

Result reporting also changed:

- `ImageCacheSource` and `ImageLoadResult.CacheSource` were replaced by `ImageLoadOrigin` and `ImageLoadResult.Origin`.
- Inspect `ImageLoadResult.SourceValidation` to distinguish current, revalidated, unverified and not-required source states.
- Use `ImageLoadResult.ContentId` when a stable content identity is available.
- `ImageLoadSourceKind.Image` is now `ImageSourceKind.Borrowed`. A `BorrowedImageSource` never transfers ownership of its `IImage` to AtomUI.

ImagePreviewer additionally exposes `ImageSwitchMode`. `Immediate` clears the old display when switching; `WaitForLoaded` retains the previous loaded image until the new item is ready.

## Control Design Token inheritance: seal terminal tokens

Every concrete type marked with `[ControlDesignToken]` must now be a non-generic, top-level `sealed` class. Every inheritance layer between the terminal token and `AbstractControlDesignToken` must be explicitly marked; reusable layers must be abstract.

Before:

```csharp
[ControlDesignToken]
public class ProductCardToken : AbstractControlDesignToken
{
    public double HeaderHeight { get; set; }
}

[ControlDesignToken]
public class CompactProductCardToken : ProductCardToken
{
    public double CompactPadding { get; set; }
}
```

After:

```csharp
[ControlDesignToken]
public abstract class CommonProductCardToken : AbstractControlDesignToken
{
    public double HeaderHeight { get; set; }
}

[ControlDesignToken]
public sealed class CompactProductCardToken : CommonProductCardToken
{
    public double CompactPadding { get; set; }

    public override void CalculateTokenValues(bool isDarkMode)
    {
        base.CalculateTokenValues(isDarkMode);
        CompactPadding = EffectiveGlobalToken.PaddingXS;
    }
}
```

The generator flattens valid inherited properties into the terminal token schema. Do not hide or override token properties, use generic or nested token types, or omit the direct base call from the first statement of an overriding `CalculateTokenValues` method. Diagnostics `ATOMUIGEN020` through `ATOMUIGEN026` identify these invalid contracts.

`ColorPickerToken` is now sealed. Applications and third-party packages must not derive from it; customize ColorPicker through theme token values and templates. If a package intentionally offers token inheritance, publish a separate `[ControlDesignToken] public abstract ...Token` definition layer and derive sealed terminal tokens from it.

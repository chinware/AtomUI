# AtomUI 6.1.1 API Change Examples

This document supplements the main `6.1.1` release notes with the most important API changes and migration examples from `6.1.0`.
For the authoritative release entries, see the repository root `CHANGELOG.md` and `CHANGELOG.zh-CN.md`.

Chinese version: [6.1.1 API 变更示例](6.1.1-api-changes.zh-CN.md).

## ListView Selection Model Migration

`6.1.1` moves ListView selection state to an internal stable model and exposes it through the read-only `IListViewSelection` facade:

- `Selection` changes from a settable Avalonia `ISelectionModel` to a read-only `IListViewSelection`.
- `SelectedItems` changes from a settable `IList?` to a read-only `IReadOnlyList<object?>`.
- `SelectedItem` and `SelectedValue` are now read-only snapshots.
- `SelectedIndexes` is added as a read-only property.
- `ItemKeySelector` is added for preserving selection by stable business keys.
- `SelectionChanged` event args change from Avalonia `SelectionChangedEventArgs` to `ListViewSelectionChangedEventArgs`.
- The old `ListCollectionViewChangedEventArgs` type is removed; no public event in `6.1.1` uses that type.

### Setting the Selection Model Directly

#### 6.1.0

```csharp
var selection = new SelectionModel<object>
{
    Source = customers
};
selection.Select(3);

listView.Selection = selection;
```

#### 6.1.1

```csharp
listView.SelectedIndex = 3;
```

Multiple-selection scenarios should operate on the existing `Selection` facade:

```csharp
listView.Selection.Clear();

foreach (var sourceIndex in selectedSourceIndexes)
{
    listView.Selection.Select(sourceIndex);
}
```

### Binding or Setting SelectedItems

#### 6.1.0

```xml
<atom:ListView
    ItemsSource="{Binding Customers}"
    SelectionMode="Multiple"
    SelectedItems="{Binding SelectedCustomers, Mode=TwoWay}" />
```

#### 6.1.1

`SelectedItems` is now the ListView read-only selection snapshot.
To synchronize selection results into a ViewModel, listen to `SelectionChanged` and read the complete current snapshot from the control:

```xml
<atom:ListView
    x:Name="CustomersList"
    ItemsSource="{Binding Customers}"
    SelectionMode="Multiple"
    SelectionChanged="HandleCustomersSelectionChanged" />
```

```csharp
private void HandleCustomersSelectionChanged(object? sender, ListViewSelectionChangedEventArgs e)
{
    if (sender is not ListView listView)
    {
        return;
    }

    SelectedCustomers.Clear();

    foreach (var customer in listView.SelectedItems.OfType<Customer>())
    {
        SelectedCustomers.Add(customer);
    }
}
```

To replay selection from ViewModel state, call `Selection` with source indexes:

```csharp
listView.Selection.Clear();

for (var index = 0; index < Customers.Count; index++)
{
    if (selectedCustomerIds.Contains(Customers[index].Id))
    {
        listView.Selection.Select(index);
    }
}
```

### SelectionChanged Event Args

#### 6.1.0

```csharp
private void HandleSelectionChanged(object? sender, SelectionChangedEventArgs e)
{
    foreach (var item in e.AddedItems)
    {
        AddSelection(item);
    }

    foreach (var item in e.RemovedItems)
    {
        RemoveSelection(item);
    }
}
```

#### 6.1.1

```csharp
private void HandleSelectionChanged(object? sender, ListViewSelectionChangedEventArgs e)
{
    foreach (var item in e.SelectedItems)
    {
        AddSelection(item);
    }

    foreach (var item in e.DeselectedItems)
    {
        RemoveSelection(item);
    }
}
```

Use `SelectedIndexes` and `DeselectedIndexes` when indexes are needed:

```csharp
private void HandleSelectionChanged(object? sender, ListViewSelectionChangedEventArgs e)
{
    foreach (var sourceIndex in e.SelectedIndexes)
    {
        MarkSelected(sourceIndex);
    }

    foreach (var sourceIndex in e.DeselectedIndexes)
    {
        MarkDeselected(sourceIndex);
    }
}
```

### SelectedValue Replay

#### 6.1.0

```xml
<atom:ListView
    ItemsSource="{Binding Customers}"
    SelectedValueBinding="{Binding Id}"
    SelectedValue="{Binding SelectedCustomerId, Mode=TwoWay}" />
```

#### 6.1.1

`SelectedValue` is now calculated from the current selection.
To write a selected value back into the control, first find the source index in the data source, then set `SelectedIndex`:

```xml
<atom:ListView
    x:Name="CustomersList"
    ItemsSource="{Binding Customers}"
    SelectedValueBinding="{Binding Id}"
    SelectionChanged="HandleCustomerSelectionChanged" />
```

```csharp
private void ApplySelectedCustomerId(EntityKey? selectedCustomerId)
{
    CustomersList.SelectedIndex = selectedCustomerId is null
        ? -1
        : FindCustomerSourceIndex(selectedCustomerId.Value);
}

private void HandleCustomerSelectionChanged(object? sender, ListViewSelectionChangedEventArgs e)
{
    SelectedCustomerId = CustomersList.SelectedValue is EntityKey key ? key : null;
}

private int FindCustomerSourceIndex(EntityKey selectedCustomerId)
{
    for (var index = 0; index < Customers.Count; index++)
    {
        if (Customers[index].Id == selectedCustomerId)
        {
            return index;
        }
    }

    return -1;
}
```

### Stable Business Keys

When the same item can be filtered, grouped, paged, or re-projected, provide `ItemKeySelector`.
This lets selection state follow the business key instead of the current visible row position:

```csharp
CustomersList.ItemKeySelector = item => item switch
{
    Customer customer => customer.Id,
    IListItemData data => data.ItemKey,
    _ => null
};
```

`Select` and `Transfer` have already moved internally to the new source index / item key semantics.
Custom ListView-derived controls should prefer `Selection.IsSelected`, `Selection.Select`, and `Selection.Deselect`.

## ListItemData and SelectOption Migration

`6.1.1` removes `IListItemData.IsSelected` / `ListItemData.IsSelected`.
Selection state is no longer written onto data items; it is owned by the ListView selection model.

`ListItemData`, `GroupListItemData`, and `SelectOption` also change from records to classes.
Code that inherits these types should change from `record` to `class`, and code that used `with` expressions should explicitly create a new instance.

### Default Selected Data Items

#### 6.1.0

```csharp
var item = new ListItemData
{
    Content = customer,
    ItemKey = customer.Id,
    IsSelected = true
};
```

#### 6.1.1

```csharp
var item = new ListItemData
{
    Content = customer,
    ItemKey = customer.Id
};

listView.Selection.Select(sourceIndex);
```

### Record-Derived Types

#### 6.1.0

```csharp
public record RichSelectOption : SelectOption
{
    public string? Description { get; init; }
}

var next = option with
{
    Header = "Updated"
};
```

#### 6.1.1

```csharp
public class RichSelectOption : SelectOption
{
    public string? Description { get; init; }
}

var next = new RichSelectOption
{
    Header = "Updated",
    Content = option.Content,
    ItemKey = option.ItemKey,
    Group = option.Group,
    IsEnabled = option.IsEnabled,
    Description = option.Description
};
```

## WindowTitleBar Title Alignment

`6.1.1` adds `WindowTitleBar.TitleAlignment` and `Window.TitleAlignment`.
The default `Auto` mode chooses the title layout by platform:

- macOS uses `WindowCenter` by default.
- Windows and Linux use `Left` by default.

If previous code used custom padding, margin, or left/right add-on widths to adjust the title position, migrate to the public property.

### Configure the Window Title Directly

```xml
<atom:Window
    Title="Settings"
    TitleAlignment="WindowCenter">
    <!-- window content -->
</atom:Window>
```

### Use WindowTitleBar Directly

```xml
<atom:WindowTitleBar
    Title="Settings"
    TitleAlignment="Center"
    LeftAddOn="{Binding Breadcrumb}"
    RightAddOn="{Binding Actions}" />
```

`Center` centers the title within the title bar content area.
`WindowCenter` aligns it to the physical window center.

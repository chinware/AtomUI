# AtomUI 6.1.8 API 变更示例

AtomUI 6.1.8 调整了三个公共扩展边界：DataGrid 数据/查询状态、图片来源与缓存策略、Control Design Token 继承。本页给出从 6.1.7 升级时必须完成的迁移。

英文版：[AtomUI 6.1.8 API Change Examples](6.1.8-api-changes.md)。

## 快速对照

| 领域 | 6.1.7 | 6.1.8 迁移 |
| --- | --- | --- |
| DataGrid | 集合型 `ItemsSource`、可变 `DataGridCollectionView` 查询状态与 Item/Index 选择 | 本地数据包装为 `DataGridLocalSource<T>`，或实现 `IDataGridSource`；改用不可变 `DataGridQuery`、`DataGridSelectionState` 与稳定 Row/Field Key |
| 图片加载 | `ImageLoadSource`、`ImageLoadSourceKind` 与合并的 `ImageCacheMode` | 构造对应的封闭 `ImageSource` 子类，并分别选择 `ImageCacheReadPolicy` 与 `ImageCacheStoragePolicy` |
| Control Design Token | 具体 Token 类可以不封闭并直接作为继承层 | 终端 `[ControlDesignToken]` 类改为 `sealed`；需要共享继承时引入显式标记的抽象 Token 层 |

## DataGrid：改用 Range Source 与不可变状态

### 将本地集合包装为 `DataGridLocalSource<T>`

`DataGrid.ItemsSource` 不再接受任意 `IEnumerable`，而是接受 `IDataGridSource`；Source Schema 负责声明稳定 RowKey 与可查询字段。

迁移前：

```csharp
public ObservableCollection<Customer> Customers { get; } = LoadCustomers();
```

```xml
<atom:DataGrid ItemsSource="{Binding Customers}" />
```

迁移后：

```csharp
public sealed class CustomersViewModel : IDisposable
{
    private readonly ObservableCollection<Customer> _customers = LoadCustomers();

    public CustomersViewModel()
    {
        Customers = DataGridLocalSource.Create(
            _customers,
            DataGridLocalSourceDescriptor.For<Customer>(
                    static customer => DataGridRowKey.FromInt64(customer.Id))
                .Field(CustomerFields.Name, static customer => customer.Name)
                .Field(CustomerFields.CreatedAt, static customer => customer.CreatedAt));
    }

    public DataGridLocalSource<Customer> Customers { get; }

    public void Dispose() => Customers.Dispose();
}

public static class CustomerFields
{
    public static readonly DataGridFieldId Name = new("name");
    public static readonly DataGridFieldId CreatedAt = new("createdAt");
}
```

```xml
<atom:DataGrid ItemsSource="{Binding Customers}">
    <atom:DataGrid.Columns>
        <atom:DataGridTextColumn Header="Name"
                                 FieldId="{x:Static vm:CustomerFields.Name}"
                                 Binding="{Binding Name}" />
        <atom:DataGridTextColumn Header="Created"
                                 FieldId="{x:Static vm:CustomerFields.CreatedAt}"
                                 Binding="{Binding CreatedAt}" />
    </atom:DataGrid.Columns>
</atom:DataGrid>
```

`DataGridLocalSource<T>` 由调用方持有并负责 `Dispose`。RowKey 投影必须稳定且唯一；所有用于排序、过滤或分组的字段都要注册到 Descriptor，纯展示列可以不设置 `FieldId`。

远端或虚拟数据请直接实现 `IDataGridSource`：

```csharp
public interface IDataGridSource
{
    DataGridSourceSchema Schema { get; }

    ValueTask<DataGridRangeResult> FetchAsync(
        DataGridFetchRequest request,
        CancellationToken cancellationToken);

    event EventHandler? Invalidated;
}
```

`FetchAsync` 会收到不可变 Query、分页、分组展开、Range 与 Snapshot Scope。实现必须只返回请求范围并配合取消；只有 Source 确实支持编辑、移动、Key 查找或批量选择时，才实现对应的可选能力接口。

### 替换可变 CollectionView 查询 API

旧 `DataGridCollectionView` 家族以及可变的排序/过滤/分组 Description 集合已移除。请构造不可变 `DataGridQuery`，或使用 DataGrid 的查询辅助方法。

迁移前：

```csharp
grid.CollectionView!.SortDescriptions.Add(
    new DataGridSortDescription(nameof(Customer.Name), ListSortDirection.Ascending));
```

迁移后：

```csharp
grid.Query = grid.Query.WithSorts(
    [new DataGridSort(new DataGridFieldId("name"), DataGridSortDirection.Ascending)]);

// 也可以让 DataGrid 校验并更新当前 Query：
grid.SetSort(new DataGridFieldId("name"), DataGridSortDirection.Ascending);
```

以下列成员已移除：`SortMemberPath`、`CustomSortComparer`、`FilterMemberPath`、`FilterTextMemberPath`、`FilterValueMemberPath`、`FilterChildrenMemberPath` 及相关成员路径过滤属性。请使用 `DataGridColumn.FieldId`，并在 Source Schema 中声明支持的排序、过滤和分组能力。`DataGridColumn.CanUserSort` 现在是可空值；`null` 表示继承 DataGrid 级策略和 Source 能力。

分组 API 改用稳定 GroupKey：

```csharp
grid.CollapseGroup(groupKey);
grid.ExpandGroup(groupKey);
```

原来把 `DataGridCollectionViewGroup` 传给 `CollapseRowGroup` / `ExpandRowGroup` 的代码，应改用 Range Source 结果提供的 `DataGridGroupKey`。

### 以声明式选择替代 Item/Index 选择

`SelectedIndex`、`SelectedItem`、`SelectedItems`、`CollectionView` 和路由 `SelectionChangedEvent` 已移除。选择由不可变 `DataGridSelectionState` 表达，当前行由 `CurrentRowKey` 标识。

迁移前：

```csharp
grid.SelectedIndex = 0;
grid.SelectionChanged += OnSelectionChanged;
```

迁移后：

```csharp
var key = DataGridRowKey.FromInt64(customer.Id);

grid.Selection = new DataGridSelectionState(
    explicitKeys: [key],
    allMatchingQuery: null,
    indexIntervals: [],
    excludedKeys: []);
grid.CurrentRowKey = key;

grid.SelectionChanged += (_, args) =>
{
    DataGridSelectionState oldSelection = args.OldSelection;
    DataGridSelectionState newSelection = args.NewSelection;
};
```

`SelectionChanged` 现在是普通 `EventHandler<DataGridSelectionChangedEventArgs>`，只报告旧、新声明式状态，不会为了事件物化未加载项。持久化选择时必须保存稳定 RowKey，不能保存 View Index。

## 图片加载：构造强类型 `ImageSource`

`ImageLoadSource` / `ImageLoadSourceKind` 已替换为封闭的 `ImageSource` 层次 / `ImageSourceKind`。工厂调用按下表迁移：

| 6.1.7 | 6.1.8 |
| --- | --- |
| `ImageLoadSource.FromUri(uri)` | HTTP(S) 使用 `new HttpImageSource(uri)`，其他来源使用对应具体类型 |
| `ImageLoadSource.FromFile(path)` | `new FileImageSource(path)` |
| `ImageLoadSource.FromAsset(uri)` | `new AssetImageSource(uri)` |
| `ImageLoadSource.FromStorageFile(file, cacheKey, version)` | `new StorageFileImageSource(file, revision)` |
| `ImageLoadSource.FromBytes(bytes, cacheKey, version)` | `new BytesImageSource(bytes, displayName)` |
| `ImageLoadSource.FromStream(open, cacheKey, version, name)` | `new StreamImageSource(open, identity, revision, name)` |
| `ImageLoadSource.FromImage(image, cacheKey)` | `new BorrowedImageSource(image, displayName)` |

迁移前：

```csharp
var item = new ImagePreviewItem(
    ImageLoadSource.FromUri(new Uri("https://example.test/photo.png")))
{
    RequestOptions = new ImageRequestOptions
    {
        CacheMode = ImageCacheMode.Reload
    }
};
```

迁移后：

```csharp
var item = new ImagePreviewItem(
    new HttpImageSource(new Uri("https://example.test/photo.png")))
{
    RequestOptions = new ImageRequestOptions
    {
        CacheRead = ImageCacheReadPolicy.RefreshSource,
        CacheStorage = ImageCacheStoragePolicy.MemoryAndDisk
    }
};
```

`ImageSource.Parse` / `ImageSource.TryParse` 仍支持绝对 HTTP(S)、`avares`、`file` 和平台绝对路径字符串。已知来源类型与所有权时优先使用显式构造器。

### 将缓存读取行为与缓存存储拆开

`ImageCacheMode` 原来混合了两个独立决定。请迁移到 `ImageRequestOptions.CacheRead` 与 `CacheStorage`：

| 原模式 | `CacheRead` | `CacheStorage` |
| --- | --- | --- |
| `Default` | `ValidateSource` | `MemoryAndDisk` |
| `Reload` | `RefreshSource` | `MemoryAndDisk` |
| `NoStore` | 按需求选择读取策略 | `None` |
| `CacheOnly` | `CacheOnly` | 按需求选择存储策略 |

普通请求默认使用 `ValidateSource`。`RefreshSource` 强制本次访问来源；`PreferCache` 可以不按普通规则校验来源而使用缓存；`CacheOnly` 在 miss 时失败，不访问来源。

结果报告也有以下变化：

- `ImageCacheSource` / `ImageLoadResult.CacheSource` 替换为 `ImageLoadOrigin` / `ImageLoadResult.Origin`。
- 使用 `ImageLoadResult.SourceValidation` 区分 current、revalidated、unverified 和 not-required 来源状态。
- 有稳定内容身份时使用 `ImageLoadResult.ContentId`。
- `ImageLoadSourceKind.Image` 更名为 `ImageSourceKind.Borrowed`；`BorrowedImageSource` 永远不会把 `IImage` 所有权转交给 AtomUI。

ImagePreviewer 还新增 `ImageSwitchMode`。`Immediate` 在切换时立即清空旧图；`WaitForLoaded` 在新图就绪前保留上一张已加载图片。

## Control Design Token 继承：封闭终端 Token

所有标记 `[ControlDesignToken]` 的具体类型现在必须是非泛型、顶级 `sealed` 类。终端与 `AbstractControlDesignToken` 之间的每一层都必须显式标记，可复用层必须为抽象类。

迁移前：

```csharp
[ControlDesignToken]
public class ProductCardToken : AbstractControlDesignToken
{
    public double HeaderHeight { get; set; }
}

[ControlDesignToken]
public class CompactProductCardToken : ProductCardToken
{
    public double CompactPadding { get; set; }
}
```

迁移后：

```csharp
[ControlDesignToken]
public abstract class CommonProductCardToken : AbstractControlDesignToken
{
    public double HeaderHeight { get; set; }
}

[ControlDesignToken]
public sealed class CompactProductCardToken : CommonProductCardToken
{
    public double CompactPadding { get; set; }

    public override void CalculateTokenValues(bool isDarkMode)
    {
        base.CalculateTokenValues(isDarkMode);
        CompactPadding = EffectiveGlobalToken.PaddingXS;
    }
}
```

Generator 会把有效的继承属性平铺到终端 Token Schema。不要隐藏或重写 Token 属性，不要使用泛型/嵌套 Token，也不要在重写 `CalculateTokenValues` 时遗漏第一条直接 base 调用。诊断 `ATOMUIGEN020` 到 `ATOMUIGEN026` 会指出这些非法契约。

`ColorPickerToken` 现在是 `sealed`。应用和第三方包不能继续派生它，应通过 Theme Token 值与模板定制 ColorPicker。若包确实要提供 Token 继承扩展点，请单独发布 `[ControlDesignToken] public abstract ...Token` 定义层，并从中派生封闭的终端 Token。
